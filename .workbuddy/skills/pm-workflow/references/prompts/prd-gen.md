# 生成 PRD 文档

基于以上我们的全部对话，请整理成一份标准的产品需求文档(PRD)。
要求结构清晰，包含以下章节：
1. 文档信息（标题/版本/作者/日期/变更记录）
2. 需求概述（背景、目标、范围含/不含、成功指标含埋点）
3. 用户与场景（2-3 个 persona + 主/次/异常场景）
4. 用户旅程图（Mermaid 旅程图 + 情绪/痛点）
5. 业务流程与场景流程图（整体/场景/操作，Mermaid）
6. 功能需求（**页面截图 + 功能说明**：每个功能点先放对应原型页面截图 `![名称](screenshots/<screen>.png)`，截图已存在于 `screenshots/` 由 `gen_screenshots.js` 渲染；图片下方再写 功能范围/边界/功能详述/操作方式/数据流；抽象逻辑可补 Mermaid。每个功能点至少 1 张截图，禁止只用文字/线框替代）
7. 非功能需求（性能/安全/兼容/可用）
8. 数据需求（模型/字典/流向）
9. 设计需求（原型说明）
10. 技术要求
11. 验收标准
12. 风险与依赖（含影响面分析）
13. 里程碑/发布
14. 附录（术语、参考、来源标注）

用 Markdown 格式输出，流程图用 Mermaid 代码块。
