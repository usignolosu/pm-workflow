# PM 校验点（B 模式）— DRAFTING 阶段中途介入

> 默认模式（A）是主编排/Specialists自己跑到方案评审门统一让 PM 看。**B 模式**额外在 DRAFTING 阶段插入 3 个 PM 校验点，让 PM 渐进式确认。

---

## 三个校验点位置

| 校验点 | 触发位置 | PM 审查内容 | 默认动作 | 超时兜底 |
|---|---|---|---|---|
| **PM-Check 1：画像确认** | 用户研究产出后、战略启动前 | 01_user_research.md（画像/场景/痛点） | 让 PM 校画像偏差 | 跳过自动进 |
| **PM-Check 2：功能确认** | 指标产出后、合规/原型启动前 | 01+02+03 摘要（用户/功能/指标） | 让 PM 看功能清单有无遗漏 | 跳过自动进 |
| **PM-Check 3：技术方案预审** | 原型-A1 产出后、评审组审核前 | 05_solution.md 摘要（选型/数据模型/API） | 让 PM 预知技术可行性 | 跳过自动进 |

---

## PM 启动方式

任何时候 PM 可以说：

- **"开启 B 模式"** → 之后所有 REQ 默认带 PM 校验点
- **"开启 A 模式"** → 关闭 PM 校验点回到默认
- **"本次要 B 模式"** → 仅本 REQ 启用
- **"B 模式跳过校验 1"** → 单次跳过某个校验点

---

## 每个校验点的执行流程

### PM-Check 1：画像确认（耗时 ~2 分钟）

PM 看到：
```
=== PM-Check 1：画像确认 ===
REQ-XXX 用户研究已产出用户画像：
  • 画像 A：xxx  （基于 [需求推断/历史 PRD/通用行业认知]）
  • 画像 B：xxx
  • 画像 C：xxx

✅ 通过 → 进战略
➕ 加画像 → 用户研究补画像
🔄 改画像 → 用户研究修订
⏭️ 跳过 → 自动进战略（30 分钟无响应）
```

### PM-Check 2：功能确认（耗时 ~5 分钟）

PM 看到：
```
=== PM-Check 2：功能确认 ===
基于画像抽出的功能清单（FR-001 ~ FR-020）：
  • FR-001：xxx（关联画像 A）
  • FR-002：xxx（关联画像 B）
  ...

未覆盖的场景：
  ⚠️ 画像 A 想做 xxx，PRD 没提（PM 确认是否要做）

✅ 通过 → 进合规/原型
➕ 加 FR → 战略补
🔄 改 FR → 战略修订
⏭️ 跳过 → 自动进
```

### PM-Check 3：技术方案预审（耗时 ~5 分钟）

PM 看到：
```
=== PM-Check 3：技术方案预审 ===
原型-A1 已出 05_solution.md：
  • 技术选型：xxx、xxx
  • 数据源：xxx → 降级链路：xxx
  • 数据模型：xx 张表
  • API：xx 个端点
  • TDL：xx 条决策

⚠️ 风险提示：xx、xx

✅ 通过 → 进评审组审核
🔄 改选型 → 原型修订
⏭️ 跳过 → 自动进
```

## 实施细节

### 1. state.json 增加字段

```json
{
  "current_req": "REQ-XXX",
  "phase": "DRAFTING",
  "step": "用户研究",  // 当前所在 Agent
  "scale": "complex",
  "mode": "B",  // A 或 B
  "pm_check_pending": null,  // 或 "PM-Check 1" / "PM-Check 2" / "PM-Check 3"
  "loop_count": 0
}
```

当主编排推进到 PM 校验点时：
- `phase: DRAFTING`
- `pm_check_pending: "PM-Check 1"`
- `step: "waiting_PM"`

主编排输出"等待 PM"提示并**停下来**。

### 2. PM 响应解析

| PM 触发词 | 动作 |
|---|---|
| "通过" / "✅" | 清 pm_check_pending → 进下一阶段 |
| "加画像：xxx" / "➕ xxx" | 路由到用户研究补做 → 清 pm_check_pending |
| "改：xxx" / "🔄 xxx" | 路由到对应 Agent 修订 |
| "跳过" / "⏭️" | 清 pm_check_pending → 进下一阶段 |

### 3. 超时兜底

如果 PM 30 分钟不响应，主编排自动"跳过"，进下一阶段。这是为了不让 DRAFTING 因为 PM 没空就卡死。

---

## Scale 对校验点的影响

| scale | 默认启用校验点 | 可选性 |
|---|---|---|
| light | PM-Check 1 + 2 都跳过 | B 模式也只多 1 个（画像），其他跳过 |
| standard | PM-Check 1 可选 | PM 自由开关 |
| complex | PM-Check 1/2/3 全部默认开 | 避免事后大返工 |

---

## 与现有评审门的关系

**B 模式不替代方案评审门**。只是在 DRAFTING 中间加 PM 校验点，方案评审门照常进行。区别是：
- 方案评审门：所有产出完成后，PM 一次过
- B 模式校验点：单个 Agent 产出后，PM 即时确认

B 模式适合：需求模糊、PM 想尽早介入、避免收尾大返工。
