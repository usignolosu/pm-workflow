# 三种模式裁剪规则

模式在每次进入工作流时由系统判定 + 用户确认。模式决定：调研深度、上场角色数量、确认门次数、优先级口径、产物范围。

---

## 轻量模式（Light）

**适用**：小改动、局部优化、已知范围内的微调；无需背景调研。
**跳过**：②③ 背景调研与行业调研。
**上场角色（3）**：功能设计、PRD、QA（调研员极简参与）。
**确认门**：合并为 1 次——在 ⑥ 低保真原型确认后做一次综合确认（场景+功能+原型一起过）。
**优先级口径**：P0 / P1 / P2。
**产物**：简版 PRD（One-Pager：问题 / 目标 / 最小功能点 / 验收）+ 低保真原型 + 精简用例。
**执行形态**：会话内串行。

---

## 常规模式（Standard）

**适用**：普通任务，可能涉及已有功能点；需要一定背景但无需深究历史。
**调研**：② 轻量检索现有知识库相关功能点；③ 轻量联网 / 竞品扫描。
**上场角色（6）**：调研员、行业分析、场景梳理、功能设计、PRD、测试、QA（用例转写并入行业分析）。
**确认门**：3 次（场景门 1 / 功能表门 2 / 原型门 3）。
**优先级口径**：RICE。
**产物**：标准 PRD（14 模块）+ 低/高保真原型 + 测试用例。
**执行形态**：会话内串行。

---

## 复杂模式（Complex）

**适用**：大范围需求，需研究之前资料、跨模块影响、方案权衡。
**调研**：② 深度检索 + 知识图谱关联 + 历史 PRD 追溯；③ 深度竞品 + 多源联网 + 用例库。
**上场角色（9+）**：全量 9 角色 + 架构师 / 竞品分析 / SME。
**确认门**：3 次 + 阶段中审（关键节点额外请确认）。
**优先级口径**：RICE（含影响面分析）。
**产物**：完整 PRD + 高保真原型 + 测试用例 + 影响面分析 + 可选 5 类（技术规格 / 用户故事 / 数据模型 / API 文档 / 商业模式）。
**执行形态**：Agent 工具真·分身并行（②③ 调研并行、⑦ 产出并行）。

---

## 模式识别信号（系统自动判定参考）

| 信号 | 倾向模式 |
|------|---------|
| "小改""优化一下""调整" | 轻量 |
| "新增功能""做一个""支持 XX" | 常规 |
| "重构""平台级""从 0 到 1""涉及多个模块""参考历史" | 复杂 |
| 用户明确指定 | 以用户为准 |

> 系统给出判定后**必须**请用户确认，不可自作主张。
