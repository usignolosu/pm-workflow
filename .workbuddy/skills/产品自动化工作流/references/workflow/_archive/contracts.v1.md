# 契约 — 跨 Agent 交接

每个 Agent 接收上游产物的格式、产出下游产物的格式都规定在这里。违反契约的产出视为不合格。

## 产出防线（Guardrails）

所有 Agent 产出必须遵守以下硬性约束。违反任何一条视为不合格，门下省直接打回，无需审内容。

### 通用防线

1. **不得捏造事实**：所有用户画像、场景、竞品、指标数据必须基于输入需求推断或明确标注"假设"。严禁虚构数据、功能、接口或第三方服务。
2. **不得标 TBD**：所有产出不得出现 TBD（To Be Determined）。不确定的内容必须标注最佳猜测 + 置信度（如：80% confidence），或加方括号 ⚠️ 标记待确认项。
3. **不得写空话**：禁止出现"体验流畅"、"提升效率"、"简单易用"等无度量目标的空洞表述。每个定性描述必须附可判断条件。
4. **不得使用"等"字收尾**：清单/表格/枚举必须在产出物中被完整列举。如果确实有未穷尽项，必须标注空白位置或明确"仅列当前已知项"。
5. **不得跳级传递**：上游尚未完成的 Agent，下游不得依赖其产出。兵部必须先读到吏部的 `01_user_research.md` 才能开始。
6. **编号一致性**：任何跨文件引用（如 FR-01、画像ID）必须使用全局统一编号。不允许两个文件引用同一对象使用不同编号。
7. **无反问句**：所有产出内容必须是陈述句。Agent 不得以反问向 PM 提问（如"这个功能真的需要吗？"）。开放问题统一放到文件末尾的 `## 开放问题` 章节。
8. **边界条件必填**：每个功能详细说明必须包含"边界条件"和"离线/错误兜底策略"子节。缺失视为不合格，门下省直接打回。
9. **持久化方案必填**：每个涉及数据存储的功能必须写明持久化方式（LocalStorage / SQLite / 内存 / 不持久化）。缺失视为不合格。
10. **数据时间戳必填**：每个涉及外部数据展示的功能（行情/新闻/基金净值/预测）必须写明"数据更新时间的展示方式"及"数据时效标注"。缺失视为不合格，门下省直接打回。
11. **数据降级链路必写**：每个依赖外部接口的功能必须写明完整降级链路（主数据源 → 备用源 → 离线模拟池 → "暂不支持"提示），并说明每级降级时用户看到什么。缺少任一链路视为不合格。
12. **算法边界条件必写**：每个涉及计算/预测/统计/回测的功能必须写明算法边界条件（零输入/满输入/单值输入/整除边界/索引越界/时序靠后数据不完整）。不写直接打回。
13. **原型-实施对齐契约**：原型中的每一个交互元素（按钮/弹窗/筛选条件/分组Tab/数据字段）必须在 final_prd.md 中有对应的功能说明。原型中出现的字段（如"持仓badge"、"数据更新时间"、"分组Tab"）都必须在 final_prd.md 的验收标准中找到对应接受条件。原型产出后，门下省必须做"原型-PRD对齐检查"，检查不通过不得进入实施阶段。

### 各 Agent 专用防线

| Agent | 专用防线 |
|---|---|
| **吏部** | 不得从零编造用户。画像必须有来源标注（基于需求推断/基于通用行业认知/基于用户调研假设）。 |
| **兵部** | 功能清单中的 #编号 必须全局唯一。严禁出现 #1、#2 被两个不同功能使用。|
| **户部** | 验收标准不允许主观判词。必须用"接口响应时间 < 200ms"而非"响应要快"。违反直接打回。 |
| **礼部** | 不得给出 "建议咨询法务" 后就不做结论。必须给出明确的三选一（✅ PASS / ⚠️ NEEDS_REVIEW / ❌ BLOCK）。 |
| **工部-A1** | 技术方案必须注明每个组件/依赖的许可证类型（MIT / Apache / GPL / 商业）。不得推荐无许可的闭源组件。 |
| **工部-A2** | 原型必须至少覆盖所有 P0 功能的交互流程。不得省略 P0 核心流程。 |
| **刑部** | 测试缺陷必须标注严重程度（P0/P1/P2/P3）。P0 缺陷未修复不得通过审核。 |
| **门下省** | 所有判据必须引用原文。不得笼统说"逻辑有问题"，必须具体到哪一行、违反了契约第几条。 |

## 吏部 (user_research) 契约

**输入**：用户原始需求（来自 PM）+ 业务背景
**输出**：`01_user_research.md`，必须包含：
- 用户画像（light≥1类／standard≥2类／complex≥3类，每类含人口统计 + 行为特征 + 痛点）
- 用户场景（light≥1个／standard≥2个／complex≥3个，含触发条件 + 流程 + 期望结果）
- 关键洞察（不少于 3 条，标注重要度）

## 兵部 (strategy_risk) 契约

**输入**：吏部产出 + 用户原始需求
**输出**：
- `02_strategy_and_risk.md`：含功能清单（FR/NFR）、业务流程图（文字版）、状态机（用 mermaid）、竞品对比（light 可跳过/standard≥1个/complex≥2个）、风险清单（按 P0/P1/P2 分级）
- 状态机文件 `02_state_machine.md`（独立 mermaid 块，light 可选，standard/complex 必需）

## 户部 (metrics_value) 契约

**输入**：兵部产出
**输出**：`03_metrics_and_value.md`，必须包含：
- 北极星指标（1 个）
- 过程指标（不超过 5 个）
- 验收标准（每个 FR/NFR 对应可测量条件）
- ROI 估算或定性价值判断

## 礼部 (compliance) 契约

**输入**：兵部 + 户部产出
**输出**：`04_compliance.md`，必须包含：
- 数据隐私评估（涉及个人信息的必填）
- 行业合规检查清单（金融/医疗/教育按需启用）
- 伦理审查（涉及未成年人/敏感人群必填）
- 品牌一致性（UI 文案/视觉规范需符合 PM 既有规范）

## 工部 (engineering) 契约

**输入**：所有上游产出
**输出**：
- `05_solution.md`：技术方案、数据模型、API 列表、依赖清单
- `prototype/` 目录：可点击的 HTML 低保真原型（每个核心流程一个 HTML 文件 + index.html 导航）

**研发阶段额外产出**：
- `code/` 目录：可运行的代码
- `README.md`：运行说明

## 刑部 (audit_logic) 契约

**输入**：所有 01_drafted/ 下的产物
**输出**：`06_audit_report.md`，必须包含：
- PRD 内部逻辑自洽性检查
- 功能与指标对应性检查
- 流程闭环检查
- 角色权限清晰度检查
- 边界情况检查

**研发阶段额外产出**：
- `test_report.md`：测试用例清单、执行结果、缺陷清单、回归测试建议

## 门下省 (critic) 契约

**输入**：所有 5 个 Agent 在 01_drafted/ 下的产出
**输出**：`02_reviewed/REQ-XXX/review.md`，必须包含：
- `verdict: pass` 或 `verdict: fail`
- issues 列表（每条含：严重程度、影响哪个文件、具体问题、修改建议）
- 必须覆盖的检查项：
  - 需求完整性（是否回答了"为谁/在什么场景/解决什么问题"）
  - 逻辑一致性（PRD/原型/指标之间是否矛盾）
  - 可行性（技术方案是否能支撑原型）
  - 可测量（成功标准是否可量化）

## 尚书省 (dispatcher) 契约

**输入**：所有 Agent 产出
**输出**：
- `INDEX.md`：REQ 状态、产物清单、决策日志
- `final_prd.md`：合并后的最终版 PRD（PM 审批用）
- `prototype/` 链接到工部产出

**实施阶段额外产出**：
- `delivered.md`：交付清单

## 1. 执行摘要（Executive Summary）
- 一段话说清：为谁、解决什么、方案是什么、预期影响
- 字数控制：200 字以内

## 2. 问题陈述（Problem Statement）
- 谁遇到了什么问题、为什么痛、为什么现在解决、不解决的代价

## 3. 方案概述（Solution Overview）
- 高层描述 + 核心流程 + 系统简图（mermaid）
- 版本里程碑

## 4. 目标用户与场景（Target Users & Scenarios）
- 主要画像 + 次要画像 + 典型使用场景
- 用户旅程关键触点

## 5. 验收标准（Acceptance Criteria）
- 二元可判断条件列表

## 6. 非功能需求（NFR）
- 性能/安全/可用性/合规

## 7. 成功指标（Goals & Success Metrics）
- 北极星指标 + 过程指标 + 当前值 -> 目标值

## 8. 依赖与风险（Dependencies & Risks）
- 技术依赖 + 外部依赖 + 风险 + 应对策略

## 9. 开放问题（Open Issues）
- 未决策事项、待确认项、责任人、决策截止时间

## 10. 附录（Appendix）
- 技术架构（来自工部）+ 合规清单（来自礼部）+ 原始 Agent 产出索引
- TDL 技术决策日志
- API 契约定义

### 5.1 截图规范（工部-A2 产出）
- 截图使用 PNG 格式，1280×900 分辨率
- 每张截图上的编号用红色圆圈标注，字体 14px 加粗

- 截图文件命名：`{序号}_{页面英文名}.png`（如 `01_fund_search.png`）

### 5.2 标注索引表规范（annotation.md 产出）
