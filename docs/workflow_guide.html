一、主流程（一条 8 阶段单循环）

v5.1 的 24 状态机 + 3 mode → v7.0.0 的单循环 + 3 规模 × deliver_code 开关。流程本身不变，规模只决定哪些站跳过、哪些站加深。

二、3 规模 × 1 个正交开关 deliver_code

v5.1 的 3 mode（lean_pm / standard / enhanced）→ v7.0.0 的 3 规模 + 1 开关，更灵活也更易演进。

lightweight 小修

3 角色 · 3 阶段

  • 跳过 ②③ 调研
  • 只产低保真
  • 简版 PRD

standard 默认

13 角色 · 全流程

  • ②③ 串行调研
  • 低 + 高保真
  • 完整 14 模块 PRD
  • kg_refs 必填

complex 战略

13+3 角色 · KG 追溯

  • ②③ 深度对比
  • KG 反例防模板污染
  • 扩展 3 角色
  • 宪法 8 条逐条对照

deliver_code 正交开关

false（默认） 止于 ⑦ 高保真 + PRD + 测试用例，不改动任何代码——本轮示例需求即此模式。
true ⑦ 后继续实施改造 + 测试报告，会真实改动参考项目代码——属于高风险操作。

五、质量防线：20 条 Guardrail + 8 条宪法

机器门 validate_contract.py 在 ⑦ 末与 ⑧ 自动触发，不占打断次数。本轮示例需求实测：16/4 → 18/2 → 20/0 PASS，g001 实际抓到 13 处裸百分比，g014 强制至少 1 条反例。

20 条机器自动跑 3 条人工 · g005 / g006 / g106 宪法 8 条人工对照 spec 质量门 6 机器

编号段管谁具体内容（拦什么）
g001-g004内容真实性g001 数据要有来源或"假设"标注 · g002 禁 TBD · g003 禁"体验流畅"类空话 · g004 禁"…等"收尾
g007-g013方案完整性g007 禁反问句 · g008 边界条件必写 · g009 持久化方案必写 · g010 数据时间戳必写 · g011 降级链路必写 · g012 算法边界必写 · g013 原型-PRD 对齐
g014知识复用standard/complex kg_refs 必填，至少 1 条 role: counter_example（防模板污染）
g015原型专属HTML/方案里的颜色必须引用 design_tokens，硬编码色值 = 打回
g101-g108各角色专属用户研究：画像要标来源 · 功能设计：编号唯一 · 指标：禁主观判词 · 合规：必须三选一结论 · 测试：缺陷必标级别 · 评审：判据必须引原文到行号
g005 g006 g106流程层（人工）不跳级传递 · 跨文件编号一致 · P0 流程原型必覆盖
s001-s006PRD 结构章节完整 · 验收 EARS 句式 · user story ≥3 · FR 编号唯一 · 有 API 契约与错误码 · FR↔AC↔指标闭环
c001-c008项目宪法数据带时效 · 外部依赖必有降级链 · 计算必覆盖边界 · 原型/PRD/API 三方对齐 · 等等（从 9 条历史教训沉淀）

读审核报告举例：P0 g011 L42 — 依赖外部接口但无"降级"描述。怎么跑：python3 scripts/validate_contract.py --file runs/<run-id>/prd.md --agent bingbu --scale complex --strictness strict --merged-prd
